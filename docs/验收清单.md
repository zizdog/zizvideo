# 验收清单：哪些已经自动验过、哪些必须真机

> 用途：一份**能对账**的清单。每条都写"用什么命令证明"，命令跑得过就是真的；跑不过就是假的。
> 更新于 2026-10-11（第 16 轮：用 `FROM scratch` 的秘密武器把发布件跑进真 Linux 容器，补上"Linux 真机"这一格）。

## 一、一条命令跑全套

```bash
make preflight                  # **发布前一条命令**：把下面这些证据全跑一遍并给结论（含镜像漂移）
ZV_FORCE_CHECK=1 make check     # 版本规则 + 前端真解析(acorn) + CSS 兼容 + go vet + 单测 + 全部沙箱门禁
make smoke                      # 端到端：真服务 + 真 ffmpeg + 真 HTTP（建库/扫描/探元数据/首页/剧场/流式读取）
make linux-verify API=1         # 把**发布的 Linux 二进制**跑进真 Linux 容器：arm64 原生 + amd64(qemu)
                                #   → 起服务、SQLite 迁移、建库/扫描/首页/`Range` 流式读取全链路
make fpk && make fpk-check      # 飞牛 .fpk：真打包（官方 fnpack）后解开核对 22 项
make release-check              # 发布目录"索引 ↔ 产物"一致（make publish 会先跑它）
```

### `make preflight` 的六步与判据

| 步骤 | 判据 |
|---|---|
| 沙箱门禁与单测（`make check`） | 必须全绿 |
| 端到端冒烟（`make smoke`） | 必须通过（真服务 + 真 ffmpeg + 真 HTTP） |
| 飞牛真打包 + 自检 | 官方 `fnpack` 打包后解开核对 **23 项**（含"包内二进制与发行件同源"）；没有 fnpack 时**如实跳过** |
| 真 Linux（容器） | arm64 原生 + amd64 模拟，起服务 + SQLite + 建库/扫描/流式；没有 docker daemon 时**如实跳过** |
| 发布目录对账 | 索引↔产物一致 + Linux 验证 stamp 对账（换过产物会提示） |
| **镜像漂移** | 镜像上的 `install-zizvideo*.sh` 与本地逐字节比：一致 ✓；**同版本却字节不同 ⇒ 失败**（违反"同版本不许换字节"）；镜像还是上一版 ⇒ 如实说明"发布前正常"，不算失败 |

> 跳过（SKIP）会**单列并写明原因** —— "跳过 ≠ 验过"，这一步不许含糊过去。

**发布后复核**（`make preflight-post`）：把镜像上的产物**下载回来逐字节复算 sha256**，与索引里写的比 ——
还核对**顶层索引与版本目录索引一致性**（面板读顶层、安装器读版本目录那份；打架就会"显示一个版本、装另一个"），
并且**版本目录那份 manifest 也要能读到**（`idx` 带斜杠，落盘文件名要 sanitize）。
另外有一条判据专治"少传了东西"：**镜像 `latest` 就是本次版本、且本地有某份索引（`linux.json`/`android.json`）、
镜像却没有 ⇒ 判为漏传并失败**；镜像还是上一版时才允许"老版本没这类产物，正常"。
涵盖 `manifest.json`（darwin）、`linux.json`、`android.json`（APK 的 `file` 是路径，脚本会 sanitize 文件名）；
再核对镜像 `latest` 是否就是本版本。实测（2026-10-11）：线上 0.6.4 的 darwin 产物与 APK **两份都逐字节对上索引**。

> 为什么要"下载回来复算"：上传时的核对发生在**发布那一刻**；事后文件被换、被截断、CDN 缓存了旧版本，
> 只有重新下载算 sha256 才能发现。

> `make linux-verify` 需要本机有可用的 docker daemon；**没有时会如实跳过（退出码 2）**，不会假装验过。
> 它用 `FROM scratch`（静态二进制不需要底座镜像），所以**拉不到 Docker Hub 也能验**。
> 验过之后会把证据写进 `dist/apps/zizvideo/.linux-verified.json`（**按 sha256 记"这一份字节在真 Linux 上跑过"**），
> `make release-check` 会拿它对账：相符报 ✓；**产物换过 / 从没验过都会明确提示**（这是最危险的漂移）。

`make check` 里的独立部署门禁现在 **175 条 ok**（`tools/test-installer.sh`，全程沙箱：假 launchctl /
假 sudo / 假 open / `file://` 当镜像 / 全在 `mktemp -d` 下，并断言**一次都没碰真 sudo**）。

## 三、必须**真机**才能验的（本机没有条件，脚本会如实拒绝而不是猜）

| 待验 | 为什么本机做不了 | 到时候怎么验 |
|---|---|---|
| macOS 独立部署真跑（LaunchDaemon、真 sudo、真 TCC 授权、真签名） | 本机 zizvideo 由面板托管；铁律禁止动真机系统状态 | 在目标 Mac 上 `sudo bash install-zizvideo.sh`，然后 `sudo bash install-zizvideo.sh --verify`（应看到 `✓ 守护进程读得到`） |
| Linux **systemd 安装器**真跑（unit 文件、专用用户、开机自启） | 容器里没有 systemd/init，`install-zizvideo-linux.sh` 需要真 init 系统 | 在 NAS/服务器上 `sudo bash install-zizvideo-linux.sh` → `bash tools/verify-deploy.sh`（退出码 0） |
| 容器路径（**我们发布的 Dockerfile**） | daemon 可用但**拉不到 Docker Hub**（`alpine:3.20` 超时），所以镜像构建到 `FROM alpine` 就失败；上面的 Linux 验证用的是 `FROM scratch` 的最小镜像 | 有外网的机器：`make docker-image` → `docker run`；或先把 `alpine:3.20` 拉到本地 |
| 飞牛真机安装 | 没有飞牛设备 | `appcenter-cli install-fpk dist/fnos/zizvideo-*.fpk`，看桌面入口、向导、授权目录、升级、卸载保留/删除 |
| 安卓 App 真机 | 没有设备/不测 | 装 APK、自动更新、投屏与电视端 |
| 面板托管下的升级（读镜像 `latest`） | 需要**用户点名**才发版 | 用户点名后 `make release && make publish`，再在面板点更新 |
