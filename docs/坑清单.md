# zizvideo 坑清单（只放"删了会再踩"的结论）

格式：现象 → 根因 → 修法 → 门禁/判据。过期条目直接删，不做博物馆。

1. **网页端能删掉任意路径的文件**：删文件只信请求里的 path。
   → 必须先 `media.ValidateMediaFile(允许根, 库根, path)`，删完 `os.Stat` 回读；
   文件删不掉就**不许**删记录（否则"记录没了文件还在"是谎报）。门禁：`internal/api/media_delete_test.go`。
2. **同版本换字节重发**：产物 sha256 变了，"已装 0.1.2" 与"新装 0.1.2"不是同一份东西，
   面板的"可更新"判断也会错乱。→ 改代码就 bump 版本；`publish-mirror.sh` 默认拒绝覆盖同版本。
3. **`$VAR` 紧跟中文时 shell 报 unbound variable**：macOS 自带 bash 3.2 会把多字节字符算进变量名
   （`$VERSION（` → 变量名 `VERSION（`）。→ 中文前一律写 `${VAR}`。判据：脚本用 `/bin/bash` 跑一遍。
4. **镜像盘写不进去**：`/Volumes/ZPMirror/**` 只有 mini 的面板进程有 TCC 授权，本机/sudo/SSH 都是
   `Operation not permitted`。→ 发布走 mini 面板 HTTP 接口（`tools/publish-mirror.sh`），别试 rsync。
5. **`-buildvcs=false` 不能去掉**：Go 默认把 VCS 状态写进二进制，sha256 会随提交漂，
   镜像索引写死的校验值就对不上了。
6. **未签名的二进制每次升级都要重新授权**：macOS TCC 对 adhoc 签名按 `cdhash` 判定，一变就失效。
   → 固定自签证书 + identifier `com.zizvideo.server`（`tools/codesign-release.sh`）。
7. **前端语法错误 = 整页白屏且不给行号**：`node --check` 会放过（对象字面量少个 `}`）。
   → `make check` 用 acorn 真解析器，**缺 acorn 直接失败**，不许"缺了就跳过"。
8. **管理入口放在观看页**（用户 2026-09-22 点名）：剧场是看剧的地方，管理必须收进后台
   「剧场」页签。判据：`internal/api/frontend_assets_test.go` 的 `TestSeriesManagementOnlyInBackend`
   （观看面不许出现管理模块/admin 接口）。
9. **开关开了但前端没入口**（注册开关实例）：后端有开关 + 公开接口，前端却没有页面，
   公开状态接口也没透出这个开关 ⇒ 用户看到"开了注册，登录页没入口"。
   → 开关类功能必须同时给：公开状态字段 + 前端入口 + 后端拦截（三层都测）。
10. **子代理/测试不许动真机系统状态**：钥匙串信任、`/Library/LaunchDaemons`、`sudo`、
    `launchctl bootstrap system` 只能用假命令（`ZV_FAKE_*`）验证；真跑了却报"未真跑"= 谎报。
11. **面板文件接口的两个"静默错"**（0.1.2 发版时都踩到）：
    ① **不自动建目录** —— 往不存在的目录上传 → 400「文件不存在: <path>」，新版本第一次 `make publish` 必挂；
    ② **文件名取 multipart 的 filename** —— `curl -F "files=@/tmp/x.crt.$$"` 会把带 PID 的临时名传上去，
    线上多出垃圾名，而脚本还打印"✓ 文件名必须是这个"（**假成功**）。
    → `tools/publish-mirror.sh` 已内建：上传前先 `POST /api/v1/files/mkdir`；证书上传显式写
    `;filename=zizvideo-codesign.crt`。判据：发完看一眼镜像目录列表，只许有预期文件名。
12. **集号解析"多认"比"少认"更坏**（用户 2026-09-22 的真实片名暴露）：
    `…轰天雷炮轰豹子头！ 传108将 #AI生成.mp4` 里的 `108` 被当成了**第 108 集** ——
    因为"识别不到就靠名字里最后一个数字兜底"。那一批 29 个文件里唯一"识别成功"的就是它。
    → 兜底路径新增两条判据：① 数字两侧都是中文（传108将 / 水浒108将）不算集号；
    ② `全24集 / 共24集` 是总集数不算集号（同时补上"数字+集/话/話"的显式规则，
    保证 `剧名03集.mp4` 仍能识别）。
    **`SP01` 保持"未识别"**：SP 是"特别篇"语义，不是正片集号（用户确认保留原规则）。
    改名的推荐写法：`第01集` / `E01` / `-01-`（三种都有测试正例）。
    判据：`internal/media/episode_test.go`（真实片名 + 推荐命名 + 假集号反例）。
    教训：靠"名字里最后一个数字"兜底永远是假集号来源；新片名样式要进白名单，不许猜。
13. **整库改名 = 一堆"文件已不在但 status=ready"的僵尸记录**（用户 2026-09-22 报障，
    "首页显示这个视频放不了 / 状态：ready，刷新也没用，只有重登才行"）：
    扫描的删除是**两阶段 + 阈值**（`scanner.go` 的 reconcile）：第一次只打 `missing_since`
    （**status 不变，仍是 ready**），第二次才软删，且 `missing/live` 超过
    `scan_delete_threshold_ratio`（默认 **0.1**）就**按设计拒绝删除**——整库改名时缺失比例
    轻松到 50% ⇒ **每次扫描都拒绝，永远清不掉**，首页就会反复推荐这些播到 404 的行。
    三个放大伤害的细节，都已修：
    ① feed 只按 `status='ready'` 取行、**不看 missing_since** ⇒ 僵尸行照样进推荐流（现在排除）；
    ② `missing` 只写 `missing_since`，而媒体页的 `status=missing` 筛选按 `status` 列查 ⇒
    **永远查不到 0 条**（现在按 `missing_since` 判，且 `status=ready` 也排除缺失行）；
    ③ 扫描回执只显示"已扫描/失败"，**不显示 missing/suspected** ⇒ 用户看到"扫描成功"以为已生效
    （现在明说"疑似丢失 N 个（超过自动删除阈值，未删除）——可在「媒体」页清理"，并给了
    `POST /api/v1/libraries/{id}/purge-missing` + 界面按钮，只删记录不动文件）。
    判据：`internal/storage/feed_test.go`（缺失去重/筛选/清理三件）、
    `internal/api/media_delete_test.go`（feed 不含、missing 透出、confirm+403、不动文件）。
    教训：**"没删"必须说出来**；"数据库说 ready"和"文件还在"是两件事，别让界面把前者当后者。
    **补（2026-09-23）**：`missing_since` 只有**扫描**才写；用户改名/移走后没重新扫描时那行还是
    "`status=ready` + `missing_since` 为空"，只排除 `missing_since` 根本挡不住 ⇒
    `HandleFeedNext` 现在**出页前逐个 `os.Stat`**（每页 ≤50 次），不在的就顺手 `MarkMissing` 并剔除本页。
    判据：`media_delete_test.go` 第 ⑤ 段（删文件 + **不扫描** + 直接取 feed ⇒ 不进流且被标记缺失）。
14. **Playwright 脚本被超时杀掉会留下无头浏览器空转**（2026-09-22 把开发机烧到负载 12）：harness 只杀
    `node` 进程，Chromium 子进程会活下来；如果页面里正跑着死循环，那个 renderer 会一直吃 100%+ CPU，
    实测两个 renderer 分别 145% / 65% 持续 10 分钟，机器卡死发热。
    → **每次浏览器测试结束（或被杀）都要 `pkill -f ms-playwright`**；调试页面卡死先用 CDP
    `Debugger.pause` 抓调用栈（这次就是靠它定位到 appendItems 的别名死循环）。
    判据：跑完 `pgrep -fl ms-playwright` 必须为空；`uptime` 负载应回落。

15. **"面板 supervisor 的 `--listen`"和"zizvideo 的 `listen`"是两码事**（2026-09-23 用户报障：
    面板更新 zizvideo 后 7766 起不来 —— `zizvideo-supervise.err.log` 8 行
    `错误: --listen 只允许回环地址（实际 "0.0.0.0:7766"）`，`launchctl print` 是 `runs = 8` /
    `last exit code = 1`，而 zizvideo 二进制本身 `--version` 正常、配置也没问题）：
    面板为了"局域网直连"把 plist 写成 `--listen 0.0.0.0:7766`，可 ① 面板 supervisor 只接受回环地址，
    ② 这个参数在 supervisor 里**根本没有对应字段、从不传给子进程**（子进程只拿到 `--config`）
    ⇒ 既起不来、就算起来了也不会真绑 0.0.0.0。**真正决定监听地址的只有 zizvideo 的 config.json `listen`**
    （env `ZV_LISTEN` 可覆盖；zizvideo 自身不限制回环；安装器的 `--listen` 参数写的就是这个字段）。
    教训：**"传了参"和"生效了"是两件事** —— 跨进程的参数要一路验到子进程真的用了它，
    别只断言"plist / 命令行里有这个字符串"（面板的门禁就是这么绿的，所以整条链死了它也不知道）。

16. **模块级函数调用了别的函数里的局部函数 ⇒ 点上传只报"失败"没原因**（用户 2026-09-24 报障：
    "选文件-上传，报失败，无其它提示，点继续报 `Can't find variable: targetPayload`"；
    用户同时指出"这是最近的 bug，在'上传可选库'之前是能工作的" —— 完全正确）：

    而 `targetPayload` 定义在 `mountUpload` 内部 ⇒ 兄弟作用域看不见它（`Can't find variable`）。
    · 第一层：**门禁当时抓不到** —— `check-js-undeclared.mjs` 原来只查"赋值了但没声明"，
      调用一个"文件里明明有、但作用域里没有"的名字完全合法地溜过去了。
      已扩成第二条判据：`f(...)` / `new F(...)` 的裸标识符要能在**作用域链**（模块→函数→块）里查到，
      否则报错；本次就是它把 `upload.js:52 targetPayload` 抓出来的（修完即绿，零误报，

      ② **错误提示要在用户看到的那一刻还在** —— 收尾清理不能无差别清横幅。
    · 判据：`tools/check-js-undeclared.mjs`（作用域链调用检查）+ 端到端脚本
      `/tmp/zv-upload-ui.mjs`（选文件→上传→待审→投递库/剧场名落库→同名不同内容换名成功→

17. **服务一重启，正在传的大文件就 404**（用户 2026-09-24 点名要修）：
    后台上传的会话原来只存在内存 map（`uploadStore.live`）里，进程一重启（升级、崩溃、面板重启）
    就没了 ⇒ 客户端续传直接 `UPLOAD_SESSION_NOT_FOUND 404「上传会话不存在或已过期」`，
    用户只能从头再传（大文件动辄几百 MB）。
    修法：会话落库（迁移 **0021 upload_sessions**，`files` 存 JSON），内存降级成热缓存；
    `get()` 查不到就从库里捞回来接着传，`prune()` 同时清内存与库（TTL 不变，6 小时）。
    判据：`internal/api/upload_session_test.go` —— 传一半 → **重建一个 Server 实例**（同一份 DB，
    内存缓存必然为空）→ 接着传第二块必须 200、内容逐字节一致、扫描后正常入库。
    教训：**"重启就丢"的东西都别只放内存**；写这类门禁时不要用"清一下缓存"的测试钩子，
    直接换一个 Server 实例才骗不了自己。

18. **反向代理的请求体上限会把上传截断，而报错只会说"字节数不符"**（自动化踩到）：
    上传是 8MB 一块分片 PUT，nginx 默认 `client_max_body_size 1m` 会在中途 413/截断；
    带 `Content-Range` 的短包会被服务端当成"还要继续传"（202）→ 客户端重试即可，
    **但整文件 PUT 被截断时会 400**，而原来的文案只有"收到的字节数与声明不符"，看不出是代理干的。
    修法：该分支的报错直接带上外因提示（"若经过反向代理，请放开请求体上限（nginx: client_max_body_size）"），
    README「已知限制」里也写清怎么配。
    判据：`internal/api/upload_limits_test.go` —— 截断必须 400 且文案含"反向代理"、半截文件要删掉；
    超过单文件上限必须 413 `UPLOAD_FILE_TOO_LARGE` 且告诉用户改 `upload_max_file_mb`。

19. **离线缓存列表只有一串 `med_xxxx`、没有标题和封面**（用户 2026-09-25 报障）：
    缓存文件名就是 media id，而 id 是 `med_` + 20 位随机串（`domain.NewID`）—— 网页只能拿它去

    而且**永远没有封面**（列表是 `.cell` 文本行，根本没画图）。
    修法（两层，缺一层都不算修好）：
    · **下载那一刻就把元数据落盘**：网页把 `{id,title,cover,duration_ms}` 交给新桥
      `ZvAndroid.cacheVideo2(id, metaJson)`，原生写成与 `.mp4` 同名的 `.json` 副档；
      `listJson()` 把副档合并进清单（老缓存没副档才回落到按 id 查 API）。
    · **显示复用收藏/点赞那套卡片**：`cards.js` 的 `videoCard`（16:9 封面 + 时长角标 + 两行标题），
      点卡片走 `#/play/feed/<id>` 深链、卡片上带「删除缓存」。
    两个坑：① 副档**必须 `parentFile.mkdirs()`** —— `offline/` 目录是 DownloadManager

    ② `videoGrid()` 只吃"数据项"、卡片选项由它自己定 —— 把已经拼好的卡片再喂给它，会当成 item
    渲染成 `#` / `#/feed` 的空卡（实测踩到）。
    判据：`/tmp/zv-cache-dom.mjs`（副档 → `listCached` 带 title/cover/duration/size → 网页卡片
    有封面、真标题、`2:28` 角标、播放深链、删除按钮）。

20. **电视端（Android TV）遥控器的两个"按了没反应"**（用户 2026-09-25 要做电视端）：
    · 遥控器只有「上下左右 + 确定 + 返回 + 菜单」，而网页里可点的多半是 `div`（面板行、卡片），
      浏览器自带的焦点导航够不着 ⇒ 自己写 `js/tv.js`：几何最近元素的空间导航 + 焦点框
      （`.tv-focus`，`html.tv` 下才生效）+ 播放页专用语义（↑↓ 换视频、←→ 快退快进、确定 播放/暂停、
      长按确定=开面板）。面板行/设置行必须给 `tabindex="0"`，隐藏的复选框要 `tabIndex=-1`
      （否则遥控器停在一个看不见的框上）。
    · **`KEYCODE_MENU` 到不了 JS**：Chromium 没把它当普通按键交给网页（实测 keydown 收不到）⇒
      原生 `WebActivity.onKeyDown` 接住，再调网页注册的 `window.__zvTvMenu()`；方向键/确定能到 JS
      （DPAD_CENTER 就是 `Enter`）。
    · 长按判定用 **400ms**：`adb shell input keyevent --longpress` 只按住 ~500ms，阈值 550ms 会
      "长按当短按"（实测：面板死活打不开）。
    · 单 APK 兼容：`uses-feature leanback/touchscreen required=false` + `LEANBACK_LAUNCHER` 分类
      + `android:banner`（`drawable-nodpi/tv_banner.png` 320×180）；发布目录里仍是同一个 APK。
    判据：`/tmp/zv-tv-check.sh`（Android TV 模拟器 + 真 `adb shell input keyevent`，20 项全绿）。

21. **"图标显示声音开着，但没声音；点一下变静音、再点一下才有声"**（用户 2026-09-25 报障，
    并说明"之前就会遇到" —— 长期存在的状态不同步）：
    浏览器不许"有声自动播放"（没有用户手势时一定会被摁）。全代码里只有一处会**背着你**改 audio 状态：
    `tryPlay()` 的 catch 把 `video.muted = true` 退回静音播 —— 但它**没动 `state.soundOn` 和图标**。
    于是图标（按偏好画的）说"有声"，元素其实静音；用户点一下喇叭，`setSound(!state.soundOn)` 按**偏好**
    取反 ⇒ 变成静音（听不出变化），**再点一下**才 `muted=false` 有声音 —— 正是用户描述的"点两下"。
    修法（两条，缺一条都会有别的错法）：
    · **图标/提示只认"这一刻实际听不听得到"**：新增 `state.soundBlocked` + `effectiveSoundOn()`；
      改 audio 状态只留一处 `applySound()`（元素、图标、提示一起走）；点喇叭按 `!effectiveSoundOn()`
      决定下一态 ⇒ 被摁过之后**点一下**就开声。策略放行后（`play()` 成功且未静音）自动解除标记。
    · **App 里能自动恢复**：WebView 设了 `mediaPlaybackRequiresUserGesture=false`，页面可见就该有声 ⇒
      原生 `onWindowFocusChanged(true)` 调网页的 `window.__zvSoundNudge()`（只在"被摁过 + 偏好有声"时动作）。
      网页端没有这个口（浏览器一定要用户手势），只能由用户点一下。
    判据：`/tmp/zv-sound-ui.mjs` —— 无头 Chromium **不执行**这条策略（实测：整页 reload 后无声播放照样放行），
    所以用 `addInitScript` 精确模拟浏览器那次 `NotAllowedError`（每个文档只拒第一次，与浏览器一致）。
    旧代码 7 条红（图标 on 却 muted、点一下没声、偏好还被改掉），新代码全绿；
    App 侧用 `adb logcat -s zv-sound`（"回到前台：nudge=true/false"）证明确实调到了网页那一口。
    写这类脚本的两个坑：① 同 URL 只改 hash 是**同文档导航**，用户手势还在、策略不拦（必须整页 reload）；

42. **删文件之后"重扫为什么还看得到"**（2026-09-27 用户问："服务器上直接删文件，需要手动扫描吗？扫描有用吗？"）：
    · 默认**会自动扫**：`DefaultAutoScan` = 开、每 5 分钟一轮、事件加速、去抖 8 秒；`pumpEvents` 对**所有**
      fsnotify 事件（含 Remove）都重置去抖 ⇒ 库根内删文件会触发重扫；服务没在跑时，启动那一轮
      （`AutoScanTriggerStartup`）也会补上。
    · **缺失是两段式**（`reconcile`）：第 1 次扫只标 `missing_since`，第 2 次扫才 `ApplyDeletions` 软删记录。
      所以"删了文件扫一次还在"是设计如此，不是坏了。
    · **超阈值拒绝自动删**：缺失数 > `scan_delete_threshold_count`（默认 50）或比例 > `scan_delete_threshold_ratio`
      （默认 0.10）⇒ 只标记不删，必须在后台「媒体」页点「清理缺失记录」。整库改名/换盘最常命中。
    · 手动扫与自动扫是同一条路径（等价）；删文件 ≠ 删记录，后台「删除」默认也只删记录不动文件（坑 5）。

69. **面板的 `check-access` 自检口：输出形状与退出码都是契约**（用户 2026-10-10："zizpanel 正在进行
    应用的能用泛化改造，你要配合 check-access"）：
    · 面板调用形状（`../zizpanel/internal/permissions/externalapp.go` 的 `CheckAppAccess`）：
      `sudo -n -u <真实用户> <二进制> check-access <路径>`，**不带 `--config`**，必须是真实用户身份
      （root 会绕过 TCC，答出来的 `readable:true` 是假的）。面板逐行扫 stdout，取第一条以 `{` 开头、
      JSON 合法且带 `readable`（bool）的行 ⇒ **输出必须一行紧凑 JSON**，pretty-print 会被判为不合法。
    · **退出码永远 0**（读不到、参数不对都走 `readable:false` + `reason`）：面板把非零退出当"跑不起来"
      报 `无法运行 …`，拿退出码表达"读不了"会让用户看到一句与事实无关的报错。
    · `readable` 的判据是**真读一次**（文件 open、目录 open+Readdirnames(1)），不是 `os.Stat` ——
      TCC 拦的就是读，stat 能过 open 被拒是常态（外接卷、~/Desktop、~/Documents）。
    · ⚠️ **老版本（≤0.6.1-mvp）遇到这个动词会真把服务起起来**：Go flag 在第一个位置参数处停止，
      多余参数被忽略后走正常启动；面板又不带配置 ⇒ 按默认配置绑 7766 + 用真实数据目录。
      所以面板侧应把"没有可解析 JSON 行"一律当"该应用版本不支持自检"，别只看退出码。
    · 判据：`cmd/server/check_access_test.go`（复刻面板的 `parseAccessJSON`：输出形状一变就红，
      含"必须只有一行"、四种情况的 exit 0）；说明文档 `docs/给面板的check-access说明.md`。
