# 配置参考（自托管进阶）

> 只想装好、用起来：请看 `README.md` 与 `docs/独立部署.md`。这里是**自托管进阶**才需要的细节。

## 一、配置文件在哪

- 默认 **`~/zizvideo/config.json`**（在数据目录里；安装时 `--data-dir <路径>` 可以换数据目录）。
- 也可以用 `--config <文件>` 或环境变量 `ZV_CONFIG` 指定别的位置。
- **它是唯一真源**：面板或脚本要改配置，就改这个文件；程序每次启动/读快照都从这里取。

## 二、环境变量（与 JSON 同一份校验）

| 变量 | 说明 |
|---|---|
| `ZV_LISTEN` | 监听地址，默认 `127.0.0.1:7766` |
| `ZV_DATA_DIR` | 数据目录（DB、封面、会话密钥） |
| `ZV_DATABASE_PATH` | SQLite 路径，默认 `<data_dir>/zizvideo.db` |
| `ZV_MEDIA_ALLOW_ROOTS` | 媒体根白名单，逗号分隔；**设置后覆盖配置文件里的值** |
| `ZV_MEDIA_EXTENSIONS` | 扩展名白名单，逗号分隔 |
| `ZV_SCAN_WORKERS` | 扫描并发，1–16，默认 4 |
| `ZV_FFMPEG_BIN` / `ZV_FFPROBE_BIN` | 外部工具路径 |
| `ZV_LOG_LEVEL` | debug / info / warn / error |
| `ZV_TRUSTED_PROXIES` | 可信反代 CIDR，逗号分隔；为空则不信任任何 `X-Forwarded-*` |
| `ZV_ASSETS_DIR` | 从磁盘读前端资源（调试用；不设就是内嵌的行为） |

## 三、面板 / 脚本可以安全改的字段

配置文件是唯一真源。下面这些字段可被面板或脚本直接改写（最后一列是生效方式）：

| 键 | 含义 | 示例 | 生效 |
|---|---|---|---|
| `media_allow_roots` | 媒体根白名单（JSON 字符串数组） | `["/Users/你/Movies"]` | 立即（服务每次读快照）；也可用界面/CLI 改 |
| `listen` | 监听地址 | `"127.0.0.1:7766"` | 重启后 |
| `scan_workers` | 扫描并发 1–16 | `4` | 重启后 |
| `media_extensions` | 扩展名白名单 | `["mp4","mkv"]` | 重启后 |
| `scan_delete_threshold_ratio` / `_count` | 两阶段删除阈值 | `0.1` / `50` | 重启后 |
| `log_level` | 日志级别 | `"info"` | 重启后 |
| `ffmpeg_bin` / `ffprobe_bin` | 外部工具路径 | `"/opt/homebrew/bin/ffmpeg"` | 重启后（`/readyz` 会复核） |
| `trusted_proxies` | 可信反代 CIDR | `["127.0.0.1/32"]` | 重启后 |

## 四、媒体允许根：三种等价途径

后台「媒体允许根」界面、命令行、直接编辑 JSON 都行（服务读快照，`GET /api/v1/media/roots` 可回读）：

```bash
zizvideo roots list                        --config ~/zizvideo/config.json
zizvideo roots add    "$HOME/Movies"       --config ~/zizvideo/config.json
zizvideo roots remove "$HOME/Movies"       --config ~/zizvideo/config.json
# 每条输出一行 JSON：{"action":"add","ok":true,"path":"...","roots":[...],"config_path":"..."}
```

- `ZV_MEDIA_ALLOW_ROOTS` 一旦设置就覆盖文件里的值，此时界面与 CLI 会明确拒绝写入。
- 只要求**新增**的那条路径存在：旧根所在外接盘拔掉后，加/删别的根不会被它连坐；
  旧根会以「不可用（路径不存在）」显示，可直接删除。

## 五、媒体库根路径为什么会被拒

必须同时满足：绝对路径、`filepath.Clean` 后与原串完全一致、存在且是目录、可读、
且落在允许根内（`EvalSymlinks` 之后仍在白名单内，`/tmp` → `/private/tmp` 这类别名按真实路径比对）。
越界返回 403 并给出真实原因；被媒体库使用的允许根删不掉（会点名库名）。

## 六、运行限制与就绪判据

- SQLite 单写者：**不要把数据库放在网络盘上**；单实例，多开两个写同一份库会互相干扰。
- `GET /healthz` 只查进程；`GET /readyz` 查 DB + ffmpeg/ffprobe + 允许根 + 磁盘余量，
  **工具缺失时如实报 not ready，绝不返回 200**。
- 走反向代理时把请求体上限放开（上传是分片传的；nginx 默认 1m 会 413）：`client_max_body_size 0;`。

## 七、功能与边界（当前版本）

- **账号**：首启初始化、登录/登出、建号/改角色/禁用/重置口令；注册开关默认关（打开后登录页才出现「注册」）。
- **媒体**：媒体库增删改查 + 后台异步扫描（忽略规则、扩展名白名单、`size+mtime_ns` 增量跳过、ffprobe 元数据、
  ffmpeg 抽首帧封面、失败分类与重试、两阶段删除）；上传到媒体库/剧场、按目录导入一个剧场、按一级子目录批量建剧场。
- **播放**：Range 206 / 416 / 多段回退完整支持；游标分页 feed、单一播放实例、进度续播、收藏、点赞、剧场管理。
- **还没做**：HLS / 后台转码 / 实时转码（`direct:false` 只如实提示，不生成兼容版本）；分类、标签、批量编辑、
  推荐排序、评论 / 关注；对象存储、多实例、Prometheus 指标、备份子命令。
- **已知限制**：HEVC / AV1 能否直出由服务端按浏览器 UA 家族粗判 —— 无 HEVC 解码能力的 Chrome 会「只出声不出画面」
  且不触发 `error`，前端靠 `videoWidth === 0` 兜底提示；真正的兼容版本要等内置转码。
